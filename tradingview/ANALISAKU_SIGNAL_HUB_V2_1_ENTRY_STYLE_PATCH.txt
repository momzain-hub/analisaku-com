ANALISAKU SIGNAL HUB — PUBLIC OUTPUT CONTRACT
==============================================

PURPOSE
This file documents public-safe outputs only.
Private TradingView/Pine formulas, thresholds, periods, weights, and signal logic are intentionally not stored in this public repository.

PUBLIC SETUP STAGE
- EARLY WATCH
- CONFIRMED
- ACTIVE
- NONE / blank

PUBLIC ENTRY STYLE FROM ENGINE
- BREAKOUT
- PULLBACK
- WEAKNESS
- NONE / blank

PUBLIC STYLE-SPECIFIC EXECUTION OUTPUTS
- style_entry_low
- style_entry_high
- style_stop

The private engine selects the final entry zone and risk boundary for the active entry style. Public price levels are normalized to valid exchange price increments before being sent. The website must not derive or reproduce the private signal formula.

PUBLIC MARKET RADAR PRESENTATION
- BREAKOUT + EARLY WATCH => BREAKOUT WATCH / AREA KONFIRMASI / BATAS RISIKO RENCANA
- BREAKOUT + CONFIRMED => BREAKOUT CONFIRMED / BREAKOUT ENTRY / STOP BREAKOUT
- PULLBACK => PULLBACK / PULLBACK ENTRY / STOP PULLBACK
- WEAKNESS => BUY ON WEAKNESS / WEAKNESS ENTRY / STOP WEAKNESS

EXECUTION PLAN DERIVED FROM PUBLIC OUTPUTS
The website may calculate presentation-only metrics from approved public prices:
- PRICE POSITION: BELOW ZONE / IN ZONE / ABOVE ZONE / INVALID
- NEXT TARGET: first still-relevant target based on current price and trend direction
- RISK %: conservative risk from the upper edge of the active bullish entry zone to style_stop
- RISK : REWARD: conservative reward from the upper edge of the active bullish entry zone to NEXT TARGET, divided by the same risk
These calculations do not reproduce proprietary signal rules.

LIFECYCLE RULES
- BREAKOUT WATCH is strictly pre-breakout and must not reappear for the same pattern after that pattern has already broken.
- BREAKOUT CONFIRMED is the confirmation phase.
- A valid post-breakout retest can become PULLBACK.
- PULLBACK may persist briefly through a healthy rebound candle while the retest remains valid.
- BUY ON WEAKNESS applies only before the current pattern has broken and while the bullish structure remains valid.

RISK MODEL
- style_stop is the execution risk boundary for the current entry style.
- invalidation remains the structural invalidation of the broader setup.
- A style stop may be reached before the broader structural setup is fully invalidated.
- Different styles use different risk logic. Resulting prices are not forced to be numerically different if separate calculations legitimately normalize to the same exchange price increment.

TARGET MODEL
- target1 / target2 / target3 remain structural targets.
- The website presents NEXT TARGET rather than blindly showing Target 1 if a prior target has already been passed.

PRICE FRACTION NORMALIZATION
- Exchange price fraction rules apply for one full Exchange Day and are adjusted on the following Exchange Day when the closing price moves into another price band.
- Intraday execution-plan snapshots use the active session reference; confirmed daily-close plans prepare levels using the newly confirmed closing price band.
- Public levels are rounded conservatively according to their role (entry zone, confirmation level, risk boundary, or target).

BACKWARD COMPATIBILITY
- entry_low / entry_high remain generic structural reference areas.
- style_entry_low / style_entry_high are the active style-specific execution reference zone.
- style_stop is the active style-specific risk boundary.
- If a style exists but its style-specific output is not available yet, the frontend must show a pending state instead of substituting the generic structural level as if it were style-specific.
- When no entry style is active, generic entry/invalidation may be shown only as structural references.

FRESHNESS
- Price-level changes, style entry/risk changes, decision changes, and public Golden Cross state/age changes are included in the Signal Hub state-change comparison so public snapshots remain current.

DATA MINIMIZATION
- Signal Hub webhook payloads send only fields required for approved public outputs and Golden Cross public state/age.
- Private component scores, proprietary intermediate values, private thresholds, and internal calculation diagnostics are not included in the webhook payload.
- Worker ingestion whitelists approved fields before writing to KV.

NOTES
- These labels, zones, stops, targets, and derived metrics are analytical reference outputs, not automatic transaction recommendations.
- Decision/status remains a separate output.
- The public website must not expose calculation formulas, indicator periods, proprietary thresholds, component weights, or internal reference values.
- Private implementation belongs only in the TradingView/Pine source and other non-public secure locations.
